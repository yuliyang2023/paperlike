# 墨读 · Paperlike

面向 Paperlike 墨水屏的 macOS 独立阅读应用。使用系统 WKWebView 打开微信读书官网，所有书籍内容和阅读功能由官网提供。本工具与腾讯、DASUNG 无隶属关系。

应用使用微信读书图标，来源及生成方式见 [图标说明](Resources/ICON-SOURCE.md)。

## 使用

打开 `build/墨读 Paperlike.app`，也可复制到 `~/Applications`。在网页中登录，选择书籍开始阅读。应用有自己的网页数据存储，不会继承其他浏览器的登录状态。

- **移到 Paperlike**：按屏幕名称或厂商/产品 ID 定位显示器。窗口使用屏幕逻辑尺寸，兼容缩放和横竖屏，已适配 2200 × 1650 的 Paperlike 显示器。
- **墨水模式**：打开书籍时使用微信读书支持的 `wtheme=white` 参数选择浅色主题，使画布正文也按深色文字重新渲染；阅读区域强制白底。正文灰度、提高对比度，以极短动画保留完成事件，关闭平滑滚动和阴影。可以随时关闭。
- **页面缩放**：80%–180%，自动保存；正文字号、行距、横向翻页及背景使用微信读书自身设置，建议选择白底黑字。
- **上一屏 / 下一屏**：优先点击已识别的网页翻页按钮；连续滚动模式下每次移动一屏并保留约 100 CSS 像素重叠。输入框编辑时不触发。
- **全屏**：使用 macOS 原生全屏。
- **侧边栏大控件**：侧栏各入口扩大至 64 × 64 CSS 像素；目录、笔记、字体和通用阅读弹层采用更宽的面板及 20 CSS 像素文字。字体选项加高，内容较多时可以滚动。此适配独立于墨水模式，并随页面缩放进一步放大。
- **清晰字号设置**：字体面板顶部固定显示当前字号档位，采用大号数字及带黑色边框的原生字号滑块；点击或拖动后与正文字号同步更新，滚动字体列表时仍可见。档位沿用微信读书原有设置，不将其误标为字体磅值。

快捷键：`⌘[` / `⌘]` 翻屏，`⌘+` / `⌘−` 缩放，`⌘0` 重置，`⌘I` 墨水模式，`⌘P` 移到 Paperlike，`⌘F` 全屏，`⌘H` 首页，`⌘R` 重载。

登录状态由本机 WebKit 保存；本项目没有远程后端、遥测、账号采集或书籍导出功能。书籍权限、付费内容、书架与进度同步由微信读书处理。应用不会修改显示器分辨率或刷新率；硬件清屏和刷新模式需使用显示器自身按键。

## 构建与验证

要求 macOS 12 或更新版本，以及 Apple Command Line Tools。无 npm 依赖。

```sh
bash build.sh
"build/墨读 Paperlike.app/Contents/MacOS/PaperlikeReader" --self-test
"build/墨读 Paperlike.app/Contents/MacOS/PaperlikeReader" --smoke-test
"build/墨读 Paperlike.app/Contents/MacOS/PaperlikeReader" --reader-test
```

构建固定输出 Intel `x86_64`、macOS 12+ 的应用，并验证架构及本地临时签名。不含 Developer ID 签名或公证。

生成分发压缩包和校验文件：

```sh
bash scripts/package.sh
```

输出为 `dist/PaperlikeReader-<版本>-macos-intel.zip` 和对应的 `.sha256` 文件。解压后将应用拖入“应用程序”目录。由于没有 Developer ID 公证，首次打开可能需要在 macOS“隐私与安全性”中按系统提示允许打开。

## GitHub Actions

向 `main` 推送代码、创建 Pull Request、推送 `v*` 标签或手动运行 **Build macOS Intel**，都会触发构建。流程使用明确的 `macos-15-intel` runner，编译 `x86_64` 应用、验证签名、运行无需网络的 WebKit 自检，并上传压缩包和 SHA-256 校验文件。

在仓库 **Actions → Build macOS Intel → 成功的运行 → Artifacts** 中下载 `PaperlikeReader-macos-intel`。构建产物保留 30 天。流程不需要配置签名证书或任何仓库 Secret。

## 验证与兼容性

`--self-test` 使用临时 WebKit 数据存储，验证样式开关、上下滚动、翻页控件分支、输入保护、页面缩放和导航域名检查。`--smoke-test` 使用临时数据存储，打开微信读书官网验证页面加载、脚本注入、搜索入口和 Paperlike 检测；需要网络和可用桌面会话。这些测试不验证账号登录、付费阅读和跨设备进度同步。

`--reader-test` 使用临时数据存储打开公开试读页，等待实际翻页控件出现，翻页并验证绘制缓冲区有文字像素，再检查浅色主题、白色背景和页面截图。网站的 canvas 可能是隐藏绘制缓冲区，因此检查不依赖 canvas 元素本身的可见性。截图保存到系统临时目录并输出路径。

0.1.1 修复了加载兼容性：字号数字通过 CSS 和数据属性显示，仅在打开字体面板后更新，不插入官网组件子节点；墨水模式使用极短动画保留完成事件，并仅对正文层应用灰度滤镜。阅读导航保留原始请求信息；底部区分“正在加载正文”和“正文已就绪”。

0.1.2 修复上下滚动模式的字体设置：侧栏不再裁切子弹层，移除产生固定定位包含块的变换，字体面板按窗口边界固定显示；统一侧栏按钮间距，较矮窗口适当缩小按钮，保留大点击区域。实测滚动正文后重新打开面板、切换字体和调整字号，并回归横向翻页模式。加载状态识别同时支持上下滚动阅读。

官网使用 canvas 绘制正文，因此应用采用 WebKit 原生页面缩放，不强行更改正文 DOM 的字体或双栏布局。网站若变更翻页控件，可能需要更新 `Resources/ink.js`；官网自身的翻页功能仍可使用。CSS 模式无法停用官网所有 JavaScript 动画，也不能控制硬件刷新或保证完全无残影。
