# 墨读 · Paperlike

面向 Paperlike 墨水屏的 macOS 独立阅读应用。使用系统 WKWebView 打开微信读书官网，所有书籍内容和阅读功能由官网提供。本工具与腾讯、DASUNG 无隶属关系。

应用使用微信读书图标，来源及生成方式见 [图标说明](Resources/ICON-SOURCE.md)。

## 使用

打开 `build/墨读 Paperlike.app`，也可复制到 `~/Applications`。在网页中登录，选择书籍开始阅读。应用有自己的网页数据存储，不会继承其他浏览器的登录状态。

- **移到 Paperlike**：按屏幕名称或厂商/产品 ID 定位显示器。窗口使用屏幕逻辑尺寸，兼容缩放和横竖屏，已适配 2200 × 1650 的 Paperlike 显示器。
- **墨水模式**：打开书籍时使用微信读书支持的 `wtheme=white` 参数选择浅色主题，使画布正文也按深色文字重新渲染；阅读区域强制白底。正文灰度、提高对比度，以极短动画保留完成事件，关闭平滑滚动和阴影。可以随时关闭。
- **页面缩放**：80%–180%，自动保存；正文字号、行距、横向翻页及背景使用微信读书自身设置，建议选择白底黑字。
- **上一屏 / 下一屏**：优先点击已识别的网页翻页按钮；连续滚动模式下每次移动一屏并保留约 100 CSS 像素重叠。输入框编辑时不触发。
- **全屏**：使用 macOS 原生全屏。
- **应用界面黑白适配**：原生工具栏和页边距、行距面板统一使用白底黑字、实线边框和无渐变按钮。按钮采用 22 点半粗体，当前设置值 30 点，说明文字 20 点；墨水模式的勾选与加粗边框、键盘焦点及按下状态均可用黑白区分。工具栏保持一行，窄窗口使用清晰的黑白横向滚动条；此适配始终生效。
- **大字状态栏**：底部状态提示采用 22 点中等粗细黑字、56 点高白色状态栏，并放大加载指示器，便于在墨水屏上查看加载和排版进度。
- **侧边栏大控件**：侧栏各入口扩大至 64 × 64 CSS 像素；目录、笔记、字体和通用阅读弹层采用更宽的面板及 20 CSS 像素文字。字体选项加高，内容较多时可以滚动。此适配独立于墨水模式，并随页面缩放进一步放大。
- **清晰字号设置**：字体面板顶部固定显示当前字号档位，采用大号数字及带黑色边框的原生字号滑块；点击或拖动后与正文字号同步更新，滚动字体列表时仍可见。档位沿用微信读书原有设置，不将其误标为字体磅值。
- **页边距**：顶部“页边距”按钮打开大控件面板，通过“− / ＋”减少或增加正文左右留白，每次 20 CSS 像素；数值表示相对官网默认留白的变化。窗口较窄时会限制最大留白，保证正文仍有可读宽度。
- **行距**：顶部“行距”按钮调整正文行高，每次 0.1 倍，范围为 1.2–3.0 倍。两项均支持“恢复默认”，设置保存在本机，支持横向翻页与上下滚动模式。调整会触发官网重新排版，需稍候正文重绘完成。
- **选文弹层**：选中文字后的“复制、马克笔、波浪线、直线、写想法、AI 问书”等工具条采用 20 CSS 像素大字、至少 88 × 80 的按钮和黑色实线边框。白底黑字增强墨水屏显示，选区增加边界；划线样式和颜色选项也增加点击面积。弹层靠近窗口边缘时自动移回可见范围，窄窗口自动分两行显示。

- **AI 问书**：聊天正文和推荐问题放大至 20 CSS 像素，引用信息 18 像素，输入框 22 像素，发送按钮 56 × 56；墨水模式采用白底黑字、实线边框和清晰的禁用状态。适配独立聊天子页面，长回答保持滚动，输入框固定可见。

- **书内 Wiki 划词搜索**：在书中选中文字，点击选文工具条的“Wiki 搜索”，结果和词条在书页右侧显示，类似 AI 问书；关闭侧栏后继续原来的阅读位置。顶部“Wiki 搜索”和 ⌘K 同样搜索当前选区，未划词时提示先选中文字。侧栏支持修改关键词、返回、前进、调整字号和左右页边距，采用白底黑字及大按钮，设置单独保存。正文默认 28px，字号范围 20–48px，每次 2px；页边距每次 20px，并随侧栏宽度限制上限，保留至少 320px 阅读宽度。外部参考链接使用系统浏览器打开。

快捷键：`⌘[` / `⌘]` 翻屏，`⌘+` / `⌘−` 缩放，`⌘0` 重置，`⌘I` 墨水模式，`⌘P` 移到 Paperlike，`⌘F` 全屏，`⌘H` 首页，`⌘R` 重载，`⌘K` Wiki 搜索。

登录状态由本机 WebKit 保存；本项目没有远程后端、遥测、账号采集或书籍导出功能。书籍权限、付费内容、书架与进度同步由微信读书处理。应用不会修改显示器分辨率或刷新率；硬件清屏和刷新模式需使用显示器自身按键。

## 构建与验证

要求 macOS 12 或更新版本，以及 Apple Command Line Tools。无 npm 依赖。

```sh
bash build.sh
"build/墨读 Paperlike.app/Contents/MacOS/PaperlikeReader" --self-test
"build/墨读 Paperlike.app/Contents/MacOS/PaperlikeReader" --selection-test
"build/墨读 Paperlike.app/Contents/MacOS/PaperlikeReader" --ai-test
"build/墨读 Paperlike.app/Contents/MacOS/PaperlikeReader" --ui-test
"build/墨读 Paperlike.app/Contents/MacOS/PaperlikeReader" --wiki-test
"build/墨读 Paperlike.app/Contents/MacOS/PaperlikeReader" --wiki-selection-test
"build/墨读 Paperlike.app/Contents/MacOS/PaperlikeReader" --wiki-live-test
"build/墨读 Paperlike.app/Contents/MacOS/PaperlikeReader" --smoke-test
"build/墨读 Paperlike.app/Contents/MacOS/PaperlikeReader" --reader-test
"build/墨读 Paperlike.app/Contents/MacOS/PaperlikeReader" --layout-test
```

构建固定输出 Intel `x86_64`、macOS 12+ 的应用，并验证架构及本地临时签名。不含 Developer ID 签名或公证。

生成分发压缩包和校验文件：

```sh
bash scripts/package.sh
```

输出为 `dist/PaperlikeReader-<版本>-macos-intel.zip` 和对应的 `.sha256` 文件。解压后将应用拖入“应用程序”目录。由于没有 Developer ID 公证，首次打开可能需要在 macOS“隐私与安全性”中按系统提示允许打开。

## GitHub Actions

向 `main` 推送代码、创建 Pull Request、推送 `v*` 标签或手动运行 **Build macOS Intel**，都会触发构建。流程使用明确的 `macos-15-intel` runner，编译 `x86_64` 应用、验证签名、运行无需网络的 WebKit 自检，并上传压缩包和 SHA-256 校验文件。

在仓库 **Actions → Build macOS Intel → 成功的运行 → Artifacts** 中下载 `PaperlikeReader-macos-intel`。构建产物保留 30 天。流程不需要配置签名证书或任何仓库 Secret。

## 验证与兼容性

`--self-test` 使用临时 WebKit 数据存储，验证样式开关、上下滚动、翻页控件分支、输入保护、页面缩放和导航域名检查。`--smoke-test` 使用临时数据存储，打开微信读书官网验证页面加载、脚本注入、搜索入口和 Paperlike 检测；需要网络和可用桌面会话。这些测试不验证账号登录、付费阅读和跨设备进度同步。

`--reader-test` 使用临时数据存储打开公开试读页，等待实际翻页控件出现，翻页并验证绘制缓冲区有文字像素，再检查浅色主题、白色背景和页面截图。网站的 canvas 可能是隐藏绘制缓冲区，因此检查不依赖 canvas 元素本身的可见性。截图保存到系统临时目录并输出路径。

`--layout-test` 在试读正文上调节页边距和行距，检查画布宽度和文字像素是否实际变化，再验证恢复默认；需要网络和可用桌面会话，不在离线 CI 中运行。

`--selection-test` 使用与官网选文工具条相同结构的离线页面，在实际 WebKit 窗口中验证字体大小、背景及边框对比度、六个按钮的点击命中，以及宽窗口、窄窗口和缩放后的屏幕边界适配，并保存截图。GitHub Actions 同时运行该离线检查。

0.1.1 修复了加载兼容性：字号数字通过 CSS 和数据属性显示，仅在打开字体面板后更新，不插入官网组件子节点；墨水模式使用极短动画保留完成事件，并仅对正文层应用灰度滤镜。阅读导航保留原始请求信息；底部区分“正在加载正文”和“正文已就绪”。

0.1.2 修复上下滚动模式的字体设置：侧栏不再裁切子弹层，移除产生固定定位包含块的变换，字体面板按窗口边界固定显示；统一侧栏按钮间距，较矮窗口适当缩小按钮，保留大点击区域。实测滚动正文后重新打开面板、切换字体和调整字号，并回归横向翻页模式。加载状态识别同时支持上下滚动阅读。

官网使用 canvas 绘制正文，因此应用采用 WebKit 原生页面缩放，不强行更改正文 DOM 的字体或双栏布局。网站若变更翻页控件，可能需要更新 `Resources/ink.js`；官网自身的翻页功能仍可使用。CSS 模式无法停用官网所有 JavaScript 动画，也不能控制硬件刷新或保证完全无残影。

0.1.5 增加原生页边距和行距面板。通过正文容器宽度、预排版行高及官网 resize 重排路径更新画布，不拉伸已绘制的文字。上下滚动模式会短暂改变正文宽度以触发重排，随后恢复到设置值。该适配依赖当前官网的排版结构；固定版式、扫描图片类书籍的图内文字行距无法单独调整。

0.1.6 修复“正在重新排版正文”提示不消失的问题：排版状态独立跟踪定时器和正文就绪状态，无需等待 DOM 变化；完成后恢复“正文已就绪”，20 秒仍未完成时停止忙碌提示并显示重试建议。排版回归测试同时验证完成状态。

`--ai-test` 使用官网 AI 面板及聊天 iframe 结构的离线页面，验证父页面和子页面样式注入、问答与引用字号、黑白边框、滚动和输入区布局、推荐问题点击，以及墨水模式开关同步。GitHub Actions 同时运行；不向 AI 服务发送问题，不验证登录后的实际问答。

0.1.10 修复 AI 问书提交后聊天空白：白色背景仅应用到明确的聊天区域，保留官网全屏 Toast 提示容器的透明背景，避免遮住已生成的提问和回答。离线自检加入该提示层，防止再次出现遮挡。

0.1.11 增加应用原生界面的墨水屏适配，并修正设置面板放大后的边缘裁切。`--ui-test` 在离线页面中操作真实原生按钮，验证页边距、行距、恢复默认、工具栏滚动和墨水模式状态，检查加减按钮不会被面板裁切，并保存工具栏与面板截图。自检不写入阅读设置或窗口尺寸。

0.1.12 增加独立 Wiki 搜索窗口。`--wiki-test` 离线验证搜索结果到词条的跳转、黑白大字、透明层、中文与特殊字符 URL 编码及导航域名限制，GitHub Actions 同时运行。`--wiki-live-test` 访问中文维基百科搜索“电子纸”并打开结果，验证实际网站样式与导航；需要可访问 Wikipedia 的网络和桌面会话。Wiki 窗口使用临时 WebKit 存储，页面样式始终为墨水屏适配，不影响书籍窗口的登录和阅读进度。

0.1.13 增加 Wiki 字号和左右页边距调节，正文、表格、提示框和引用随字号放大。工具栏保持单行，窄窗口可以横向滚动。Wiki 离线和真实网站测试同时验证实际文字大小、正文宽度变化、导航后设置保留、恢复默认，以及大字页边距面板的按钮边界。

0.1.14 将 Wiki 搜索改为书内划词侧栏，复用官网的选文工具条生成“Wiki 搜索”按钮；从阅读组件的当前选区对象中获取画布选中文字，清除选区时同步清除关键词。`--wiki-selection-test` 验证画布/普通文字选区、原有复制操作、新按钮到原生侧栏的消息传递，以及侧栏关闭重开后保留书页；在 GitHub Actions 中运行。真实试读测试同时检查横向、纵向阅读组件和选文工具条已接入、正文正常绘制并可翻页。当前划词适配依赖官网组件结构，官网更新后可能需要调整。
